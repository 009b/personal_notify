# Спецификация: personal_notify

## 1. Назначение

Персональный Telegram-бот, который:
- оповещает пользователя по расписанию,
- оповещает по событиям,
- отвечает на команды.

Бот работает только для одного пользователя (владельца), доступ ограничен по `user_id`.

Пример оповещения по расписанию: в 8 утра по Москве прислать прогноз погоды в Москве в виде сообщения.

---

## 2. Функциональные блоки

### 2.1 Оповещения по расписанию

- Расписание задаётся системным cron (см. §3).
- Cron вызывает CLI-задачу бота (короткоживущий процесс), которая формирует и отправляет оповещение, после чего завершается.
- Пример: строка в crontab на 08:00 МСК → задача «погода» → сообщение в Telegram.
- Текст оповещения может обрабатываться через LLM перед отправкой (см. §6).

### 2.2 Оповещения по событиям

- Каркас приёма событий → формирование и отправка оповещения.
- Состояние событий хранится через общий интерфейс хранилища (см. §3).
- Конкретные источники и способ приёма (webhook / polling) — открытый вопрос (см. §8).

### 2.3 Ответы на команды

- Долгоживущий aiogram-процесс принимает команды от владельца.
- Доступ ограничен whitelist по `user_id`.
- Команды — см. §5.

### 2.4 Новостной дайджест

- Раз в сутки (08:00 МСК, cron) собирать посты из заданных Telegram-каналов/пабликов за последние 24 часа.
- Чтение каналов — через MTProto-юзербот (Telethon, отдельный аккаунт), т.к. Bot API не видит чужие паблики.
- Фильтрация по смыслу через LLM: убирать посты по нежелательным темам (`exclude_topics`, напр. «Трамп»).
- Агрегация: LLM суммирует оставшееся и группирует по темам.
- Итог — одна сводка владельцу со ссылками на исходные посты (t.me/<channel>/<msg_id>).
- Если за сутки значимых новостей нет — короткое сообщение «новостей нет».

## 3. Нефункциональные требования

| Параметр       | Требование                                                        |
|----------------|-------------------------------------------------------------------|
| Планировщик    | Системный cron (без сторонних планировщиков)                      |
| Хранилище      | Общий интерфейс, легко сменить точку хранения; дефолт — SQLite (stdlib `sqlite3`) |
| Деплой         | systemd-сервис (бот) + crontab (задачи по расписанию)             |
| Логирование    | TODO (уровень, хранение)                                          |
| Безопасность   | Только whitelist `user_id`                                        |
| Python         | 3.12+                                                             |

## 4. Интеграция с LLM (Ollama)

- Ollama развёрнута локально как сервис (`127.0.0.1:11434`) и вызывается при необходимости использовать LLM.
- В составе бота — обвязка вокруг использования Ollama: вызов модели для обработки текста.
- Настройки и опции (включая выбор модели) задаются в конфиге; есть дефолтная модель и возможность сменить.
- Текущее применение: обработка текста оповещений (первое применение — погода).
- Для погоды LLM вызывается с отключёнными рассуждениями (`think=False`) — быстрее в несколько раз; результат отправляется как Telegram HTML после санитизации.

|---------------|---------------------------------------|
| `/start`      | Приветствие, проверка доступа         |

| `/status`     | Статус бота и компонентов             |

## 6. Интеграции

| Сервис   | Назначение            | Способ интеграции          | Приоритет |
|----------|-----------------------|----------------------------|-----------|
| Telegram | Канал оповещений и команд | aiogram (polling)       | высокий   |
| Telegram (чтение каналов) | Сбор постов для дайджеста | MTProto-юзербот (Telethon), session-файл | высокий |
| Gismeteo | Прогноз погоды        | общий интерфейс провайдера; открытый JSON-эндпоинт сайта (без токена) | высокий |
| Ollama   | Локальная LLM         | обвязка-сервис (HTTP API)  | высокий   |

---

## 7. Ограничения и допущения

- Бот персональный — один пользователь.
- Планировщик — системный cron, сторонние планировщики не используются.
- Лишние зависимости не добавляются.
